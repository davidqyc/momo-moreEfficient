status=ACTIVE_PROJECT_MIGRATION_ADAPTER
scope=momo-moreEfficient only

## 0. Central entry first

For a full machine migration, any problem that affects several projects at once, or any
machine-level symptom whose owner is unclear, enter the central authority first:

```text
davidqyc/workstation-ops
```

This file only runs project-level recovery and acceptance **after** the central runbook has
dispatched to MOMO. It deliberately does not restate the generic macOS, disk, permission,
network, Git, worktree or bundle procedures that live in Workstation Ops.

A MOMO project agent handles MOMO only. It does not scan or repair other project repositories.

## 1. Authority

```text
REPOSITORY=davidqyc/momo-moreEfficient
DEFAULT_BRANCH=main
PUBLIC_REPOSITORY=true
```

- Live `origin/main` wins. A migrated local checkout is **not** authority merely because it
  arrived on the new Mac; it is a copy whose freshness is unproven until re-fetched.
- Resolve current truth live, in this order: `CHAT_HANDOFF.md` → `docs/PROJECT_STATE.md` →
  the GitHub Issue/PR that `docs/PROJECT_STATE.md` points at → `AGENTS.md` →
  `docs/AGENT_SKILLS_CONNECTOR.md`.
- Any SHA written into a handoff prompt, closeout note or this adapter is a historical
  coordinate only. Never `reset`, rebuild closed WIP, or re-merge in order to match one.
- There are no special release/governance branches. Release identity is a file
  (`docs/RELEASE_IDENTITY.md`), not a branch.

## 2. Local topology

Use home-relative paths. Do not commit real absolute user paths.

```text
canonical checkout   ~/Documents/GitHub/momo-moreEfficient
sibling checkouts    ~/Documents/GitHub/momo-<topic>-worktree      (ad hoc, disposable)
scratch worktrees    /private/tmp/momo-*                            (volatile, disposable)
repo-external files  ~/Downloads/momo-*, ~/Downloads/XiaoHeiNiao*   (handoff prompts, evidence)
```

- Detect worktrees with `git worktree list`; do not assume `.git` is a directory.
- Scratch worktrees under `/private/tmp` are volatile by design and must not be migrated.
  Recreate them from `origin` when needed.
- Only the canonical checkout is expected to carry authority, and only when it is clean and
  in sync with `origin/main`.

## 3. Non-Git recovery surface

Categories, path shapes and verification only. Never record secret values.

```text
secret carrier (iOS)     device Keychain, WhenUnlockedThisDeviceOnly, non-sync
                         -> the Maimemo API Token is device-local app state.
                            It is NOT a Mac migration artifact and is NOT recoverable
                            from, or restorable to, a Mac. It is re-entered on device.

signing identity         login keychain code-signing identities
                         -> verify by type/count/team match only; never export, never
                            reveal private material, never create or revoke.

provisioning             ~/Library/Developer/Xcode/UserData/Provisioning Profiles
                         -> regenerated by Xcode on demand; not a preservation target.

Xcode + runtimes         Xcode app, selected developer directory, iOS SDK, simulators
                         -> reinstall; verify, do not migrate piecemeal.

archives                 ~/Library/Developer/Xcode/Archives
                         -> rebuildable from tagged/merged source on GitHub. Retain an
                            uploaded build's archive only if dSYM symbolication for that
                            exact build is still wanted; App Store Connect also holds
                            symbols for uploaded builds.

local evidence           repo-external batch/smoke/review notes and handoff prompts
                         -> historical evidence. May contain real learning data, so it
                            stays out of Git. Not required to restore the project.

design source            icon/design reference packs
                         -> the shipped 1024 AppIcon master is in the repo under
                            ios/MomoMoreEfficient/Assets.xcassets. Design packs are
                            optional source material, not a build dependency.
```

**Public-repository boundary.** This repo is public. Tokens, cookies, certificates, private
keys, Keychain exports, account identifiers and unredacted API responses or learning data must
never enter Git, logs, examples or review artifacts — including while proving migration
recovery. Recovery evidence is reported as sanitized categories, never as values.

## 4. Release identity

`docs/RELEASE_IDENTITY.md` is the **single** release-identity authority. This adapter only
restates the migration-relevant expectation:

```text
release Team ID       W26LH686PD        (organization, paid program)
release Bundle ID     com.jiripple.xiaoheiniao
```

Explicitly **not** release authority:

- Xcode **Personal Team** — local development only. It must never be inferred or reused as the
  TestFlight/App Store distribution team, even if a local build or a stale branch selects it.
- the historical personal Bundle ID `com.davidqyc.momoMoreEfficient` — retained only in
  pre-migration history and local development state; it is not the release Bundle ID.

A stale feature branch or a locally modified Xcode project may still carry the personal team or
the historical Bundle ID. That is local development residue, not a release decision. Resolve
release identity from `main` plus `docs/RELEASE_IDENTITY.md`, never from whatever the working
tree happens to contain.

## 5. Recovery sequence

Central steps (machine, account, disk, Git tooling) come from Workstation Ops. Project-specific
steps only:

1. clone fresh into `~/Documents/GitHub/momo-moreEfficient`; prefer a fresh clone over trusting
   a copied checkout;
2. `git fetch --all --prune`, then read live `origin/main`;
3. read `CHAT_HANDOFF.md` and `docs/PROJECT_STATE.md` for the current single next step;
4. install Xcode, select the developer directory, install the iOS platform/simulators;
5. sign in to the Xcode account and let it re-establish signing for organization Team
   `W26LH686PD`; **freshly validate** account, team, signing identity and provisioning on the
   new Mac rather than assuming migrated keychain state is complete or correct;
6. re-read App Store Connect / TestFlight status live. Distribution status is not frozen into
   this adapter and any status written in a handoff note is historical;
7. re-enter the Maimemo API Token **on the iOS device** only when real device use resumes.

## 6. Verification

The project is not recovered because files arrived. Minimum acceptance:

```text
[ ] git remote -v resolves to davidqyc/momo-moreEfficient
[ ] working tree clean and HEAD in sync with origin/main
[ ] no local-only commits that are not already merged upstream
[ ] Swift test suite builds and passes on a simulator
[ ] Xcode resolves signing for Team W26LH686PD without manual certificate surgery
[ ] target Bundle ID on main reads com.jiripple.xiaoheiniao
[ ] App Store Connect / TestFlight status re-read live and recorded in the current Issue
```

Note: uninstall the app from the simulator before running the iOS suite; stored preferences
from an earlier install can otherwise affect test outcomes.

Passing this list restores **machine capability**. It does not by itself authorize product work.

## 7. Stop conditions

Stop and report rather than improvising if any of these appear:

- unexplained dirty state in the canonical checkout;
- local authority that is not reachable from any remote and has not been preserved;
- a project authority document that conflicts with live Git;
- a step that would require reading or exporting secret values, private keys or certificates;
- a step that would change product code, signing configuration, deployment, or touch cloud
  distribution;
- a step that would require scanning other projects.

Never `reset`, `clean`, `stash`, rebase, force-push or rewrite history to make migration
verification pass.

## 8. Resuming product work

Machine recovery and product work are separate gates:

1. Workstation Ops closes machine recovery;
2. the MOMO coordinator separately resumes the project against live `main` and the current
   Issue.

Product engineering starts only after **both**. A green verification list in section 6 is not a
product resume signal.
